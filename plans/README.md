## Background

This plan came out of a combined `review-animations` + `find-animation-opportunities`
pass on 2026-11-16/17 (not re-run as a formal audit for this plan — see each
skill invocation's own output in conversation history). That pass also
surfaced several un-planned findings, not yet turned into plans:

- Every `:hover` rule site-wide is ungated behind
  `@media (hover: hover) and (pointer: fine)` — the highest-leverage
  outstanding fix (affects all 27 pages, explicit escalation trigger).
- `.card`/`.related-card` hover transitions run 300–350ms, over the <300ms
  UI budget.
- The homepage's perpetual `caret` blink and the `glitchFlicker` hover
  effect on card titles are both continuous/frequent decorative motion with
  no named purpose under this philosophy — flagged as a brand-vs-craft
  tension for the site owner to resolve, not mechanically fixed.
- Stray `ease` (vs. the repo's own `cubic-bezier(.16,1,.3,1)`) on
  `button.generate:hover` and `.dropzone` border-color transitions.
- Generated/decoded QR results appear with no transition (teleporting
  state) on the 5 generator/scanner tool pages.
- The dark/light theme toggle hard-cuts every color on the page with no
  transition.

Run `improve-animations plan <description>` again for any of these to turn
them into their own numbered plan.
